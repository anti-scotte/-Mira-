# Mira 配合模式生成提示词

将以下整段粘贴到「生成配合模式」。本模式用于在一个运行窗口内优先获得可核验的 Hits@20 初步结论。目标墙钟时间 60 分钟，实际用时按日志记录。

```text
请为“有限预算下预测模型的决策组”生成五人、三个串行阶段的配合模式。五个席位为①研究负责人（Lead，管版本、放行和结论），②输入与交接负责人（管无标签文件和来源），③排序程序负责人（唯一维护正式排序代码，签认 S），④共识独立复核人（从无标签输入复算并签认 C），⑤揭晓与指标负责人（验签后读 DFT 标签并计数）。将旧职位中的 CHGNet、三模型和 B 名单统一改为协议中定义的 S、C。沿用现有底座。全队使用本机工作空间 1，每阶段只交一份清单，写明运行编号、文件实际位置、SHA-256、接收岗和下一步。Lead 每阶段整合一次，不为每个文件设置主管返工环。

阶段一｜接收旧产物，确定本轮入口（预算 10 分钟）。②把本轮签认协议、运行配置、模型清单、无标签候选表和参考凸包表显式绑定给③④。接收者在自己的任务里实际打开文件，核对字段、ID、行数与哈希。预期共同池 23,821 个材料、15 个模型；冠军以锁定清单为准。③同时核验正式源码、版本、调用命令和依赖。已知历史 1.0.0-formal-distance 未找回，scratch/rank.py 只用于合成测试。若现有可见文件仍无正式原件，采用我在此指定的新版本盲态复算路线：保留历史文件，另建运行编号，按已签认协议实现新入口。记录实现变更及来源；历史签认只作对照。若协议本身或变更授权确有缺项，由 Lead 一次列出。不得把寻找不可见的历史节点设为循环任务。

阶段二｜盲排、独立复核与冻结（预算 25 分钟）。③从阶段一确认的输入计算 S、C。S 用入选冠军的预测凸包距离，C 用所有入选模型预测凸包距离数值的中位数，按协议的 float64、哈希并列键及原始 ID 排序。同一次运行导出全排序、七档预算名单与两份预测稳定集合。先保存源码、配置、依赖版本、实际命令、合成测试证据和输出；每项能定位。原程序完全匹配时可复用同版本通过的测试；新实现用同一合成样例实际测试。③签认 S；④独立核查 C 分数、七档截断、并列、唯一性和预选案例，与归档名单按 ID 和顺序对照。已有低位浮点顺序差异须说明是否影响任一名单、阈值集合或前 20；影响未查清时保持盲态。同版复用须核对指纹，新版须重新签认。①汇总签认、写 freeze.json、输出可直接发群的总指纹。等待真人回传带时间的回执时保存检查点，下一轮从此处恢复。

阶段三｜揭晓并先交主结论（预算 20 分钟，另留 5 分钟交接）。⑤收到冻结回执后验签，先在所有化学体系的独特原型上复算冠军 F1，与模型卡绝对差 ≤0.02 才进入计数。按 material_id 一对一关联公开 DFT 凸包距离，有限值 ≤0 为命中；重复、缺失及非有限值报错。输出 S、C 各 20 行 CSV（ID、名次、预测分数、DFT 距离、命中），用两侧独有命中数之差核对总差。①立即报告“本轮 S 命中 __/20，C 命中 __/20，差 __ 个或打平”，附 CSV、运行入口及冻结清单的路径。另一位真人独立复算前标记“初步结论，待独立复核”。随后再补齐协议要求的预算曲线、随机基线、K=50 空白项目复跑和最终报告，列入后续验收清单。

恢复规则：可读性失败时由②显式重绑一次，接收人复验；仍失败只报缺失文件、来源、目标节点、错误原文和需要的动作。算错时只返给代码维护人修复受影响环节，并保存修订前后证据。输入与代码指纹相同的已通过节点直接复用。平台用量暂停或到时，导出已完成文件、最后通过的检查点和下一条实际命令。任何阶段均不从合成测试、预测稳定集合大小或名单重合率推测 DFT 命中数。
```
